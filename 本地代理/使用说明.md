# 本地代理使用说明（V3.2 · 纯 API 版）

## 包含文件

| 文件 | 作用 |
|---|---|
| `额度管家_本地代理.py` | 本地代理：查询各平台余额/配额、定时记录快照、向 V3.1 页面提供同步接口 |
| `accounts_config.json` | 账号配置（Key 以混淆形式保存，不落明文） |

## 这是什么

本地代理跑在你自己电脑上（只监听 127.0.0.1:8787），负责拿你的 API Key 去各平台查真实余额。V3.1 页面（React 版）通过「⬇ 从本地代理同步」按钮把查询结果写入数据库。**Key 永远不出你的电脑**，云端/页面数据库里只存余额数值，不存 Key。

## 支持的平台与采集方式

### 三档总览

| 档位 | 说明 | 平台 |
|---|---|---|
| **① API 直连（余额）** | 填 Key 自动采集真实余额，最省心 | DeepSeek、SiliconFlow、Kimi 按量、阶跃星辰 StepFun、OpenRouter、OpenAI（受限） |
| **② 订阅配额（%）** | 填 Key + `query:"quota"`，采集剩余配额% | 智谱 GLM Coding Plan、MiniMax Coding Plan、Kimi For Coding、阿里百炼免费额度（token 数） |
| **①+ 多模态资源包（积分）** | 填 Key 自动采集资源包剩余积分 | 可灵 Kling（视频/图像 API） |
| **③ 手动录入** | 无公开余额 API，去官网抄余额填入 | 即梦/Seedance（火山方舟）、豆包、文心一言、讯飞星火、腾讯混元、Claude、Gemini、Grok、零一万物、百川等 |

### ① API 直连（按量付费，采集余额）

| 平台 | 地区 | 配置方法 | 采集内容 |
|---|---|---|---|
| DeepSeek | 国内 | `api_key` | 实时余额（元） |
| SiliconFlow 硅基流动 | 国内 | `api_key` | 实时余额（元） |
| Kimi 按量（Moonshot） | 国内 | `api_key` | 实时可用余额（元，含代金券） |
| 阶跃星辰 StepFun | 国内 | `api_key` | 余额（元，含充值+赠送） |
| OpenRouter | 海外聚合 | `api_key` | Key 剩余 credits（美元，按 7.2 折算） |
| OpenAI | 海外 | `api_key` | 余额（美元，按 7.2 折算；注意官方已收紧公开接口，失败请手动维护） |

> OpenRouter 的 Key 需在后台设置 **credit limit** 才能返回剩余额度；未设上限的 Key 会提示「无限额」。

### ①+ 多模态厂商（资源包积分）

多模态生成（视频/图像）厂商多用"资源包积分"计费，与文本模型的"余额(元)"不同，这里采集的是**资源包剩余积分**：

| 平台 | 类型 | 配置方法 | 采集内容 |
|---|---|---|---|
| 可灵 Kling（视频/图像） | 多模态 | `api_key`（新版 API Key）或 `access_key`+`secret_key`（旧版） | API 资源包剩余积分 |

**可灵配置说明**（重要）：

```json
{
  "platform": "kling",
  "name": "可灵 API",
  "api_key": "你的可灵API Key"
}
```

- **鉴权两种方式**（任选其一）：
  - **新版**：可灵控制台（app.klingai.com/global/dev 或国内 klingai.kuaishou.com）→ API 管理 → 新建 API Key，填 `api_key`；
  - **旧版**：若你用的是 Access Key + Secret Key，改填 `"access_key":"你的AK","secret_key":"你的SK"`（不用填 api_key），代理会自动生成 JWT；
- **关键提醒**：可灵的 **API 计费与网页端积分是两套独立体系**——这里查的是「API 资源包」的剩余积分，网页端（klingai.com）的会员/积分不在此列；如果你的可灵只在网页端使用、没买过 API 资源包，会提示"没有购买 API 资源包"，这种请用手动录入；
- **即梦 / Seedance**：即梦（Dreamina/剪映）的生成能力在火山引擎**火山方舟**平台以 Seedance 模型提供，查询资源包余量需要火山引擎 AK/SK 做复杂签名，暂未接入自动采集——请到 火山方舟控制台 → 费用中心 → 资源包管理 抄余量后**手动录入**。

### ② 订阅配额（采集剩余配额 %）

| 平台 | 配置方法 | 采集内容 |
|---|---|---|
| 智谱 GLM Coding Plan | `api_key` + `"query":"quota"` | 剩余配额 % + 重置时间 |
| MiniMax Coding Plan | `api_key` + `"query":"quota"` | 剩余配额 % + 重置时间 |
| Kimi For Coding | `api_key` + `"query":"quota"` | 剩余配额 % + 重置时间 |
| 阿里百炼（通义千问）免费额度 | `api_key` + `"query":"quota"` | 各模型剩余免费 **token 数**（非金额） |

> 订阅配额账号显示的是剩余百分比/额度，不参与人民币余额汇总；`monthlyFee` 月费计入本月消耗与预算。

### ③ 无公开余额 API（手动录入）

以下平台**官方没有开放余额/用量查询 API**，无法在代理自动采集，请到官网控制台抄余额后手动填入（不填 Key 即为手动账号）：

| 平台 | 查看余额的入口 |
|---|---|
| 即梦 / Seedance（火山方舟） | 火山方舟控制台 → 费用中心 → 资源包管理（Seedance 资源包余量） |
| 豆包（火山引擎） | 火山引擎控制台 → 费用中心 → 账户余额 / 用量统计 |
| 文心一言（百度千帆） | 百度智能云控制台 → 千帆大模型 → 费用中心 |
| 讯飞星火 | 讯飞开放平台控制台 → 账户中心 |
| 腾讯混元 | 腾讯云控制台 → 费用中心 |
| Claude（Anthropic） | console.anthropic.com → Billing |
| Gemini（Google） | Google AI Studio / Cloud Billing |
| Grok（xAI） | console.x.ai → Billing / Credits |
| 零一万物 / 百川智能 等 | 各自开放平台控制台费用页 |

> 这些账号正常录入 `remaining`（余额）、`monthlyUsed`（本月消耗）、`totalRecharge`（累计充值）即可参与总览、趋势、预算的全部统计，只是余额数字需要你手动维护（或隔几天重新抄一次）。


## 三步开始

1. **启动代理**：`python3 额度管家_本地代理.py`（零依赖，仅标准库）。看到「已启动」才算成功；报「端口被占用」说明已有旧代理在运行，关掉旧窗口再启动。
2. **验证连通**：浏览器访问 `http://127.0.0.1:8787/api/health`，看到 `{"ok": true}` 即正常。
3. **同步到页面**：V3.1 页面 →「多账号管理」→「⬇ 从本地代理同步」，账号和余额自动写入数据库，消耗总览/趋势/预算同步联动。

## 配置示例

**按量付费账号**（DeepSeek）：

```json
{
  "platform": "deepseek",
  "name": "DeepSeek 主账号",
  "api_key": "sk-你的Key",
  "totalRecharge": 6000,
  "monthlyUsed": 0
}
```

- `totalRecharge`：累计充值（元），用量进度 = 本月消耗 ÷ 它；
- `monthlyUsed`：部署前本月已消耗（元，去平台官网账单页抄），部署后的消耗由快照自动累加。

**订阅制账号**（智谱 Coding Plan）：

```json
{
  "platform": "glm",
  "name": "智谱 Coding Plan",
  "api_key": "你的智谱Key",
  "query": "quota",
  "monthlyFee": 66,
  "validUntil": "2026-09-01",
  "remaining": 100
}
```

- `query: "quota"`：标记为订阅配额账号，采集的是**剩余百分比**（不是金额）；
- `monthlyFee`：月费（元），计入本月消耗与预算；
- `validUntil`：配额重置/到期日（也可由接口自动返回）。

> 保存后代理会自动把 `api_key` 转为 `enc1:` 混淆形式写回配置文件——打开文件看到的是乱码，属正常。

## 「采集」按钮与后台定时采集

- 页面对某账号点「采集」→ 代理立即强制查询（跳过 60 秒缓存），返回真实余额/配额并记录快照；
- 后台线程每 `poll_seconds` 秒（默认 300，可在配置里改）自动查询所有已配 Key 的账号，追加到 `balance_history.jsonl`；
- **余额下降 = 消耗**：同日首末快照差值即当日消耗；余额上升视为充值，不计负消耗。

## 微信预警（异常消耗熔断 + 余额预警 + 每日日报）

多个自建系统接入 API 时最怕**脚本跑飞/循环调用**——几十分钟就能烧掉大额余额。代理每轮采集后自动评估三类预警，命中即推送微信：

| 预警类型 | 触发条件 | 默认阈值 |
|---|---|---|
| **异常消耗熔断** | 某 Key 近 1 小时余额下降超过阈值（折算人民币） | ¥20/小时 |
| **余额/配额过低** | 按量账号余额 / 订阅账号剩余配额低于阈值 | ¥50 / 20% |
| **每日消耗日报**（可选） | 每天定点推送当日各账号消耗汇总 | 每天 9 点 |

**配置方法（二选一）**：

1. **企业微信群机器人**（推荐）：企业微信群 → 右上角 → 添加群机器人 → 复制 webhook 地址；
2. **Server 酱·Turbo**（推到个人微信）：[sct.ftqq.com](https://sct.ftqq.com) 微信扫码登录 → 复制 SendKey。

填进 `accounts_config.json` 的 `notify` 块：

```json
"notify": {
  "enabled": true,
  "channel": "wecom",
  "webhook": "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=你的key",
  "burn_threshold_per_hour": 20,
  "low_balance_threshold": 50,
  "low_quota_percent": 20,
  "cooldown": 7200,
  "daily_report": true,
  "daily_report_hour": 9
}
```

- `channel` 用 Server 酱则填 `"serverchan"` 并填 `"sendkey"`；
- `cooldown`：同一预警多少秒内不重复推送（默认 2 小时，避免刷屏）；
- **验证**：代理启动后访问 `http://127.0.0.1:8787/api/notify/test`，微信收到测试消息即配置成功；
- 未配置时预警只打印在代理窗口，不会报错。

> 说明：可灵资源包积分类账号不参与金额类阈值判定（余额下降按资源包积分计，单位不同）。

## 常见问题

| 提示 | 原因与处理 |
|---|---|
| Key 无效或没有权限(HTTP 401/403) | Key 复制不完整、多了空格或已过期，重新复制 |
| 连接平台超时 | 本机网络连不上该平台（公司/校园网可能需代理） |
| 域名解析失败 | 检查网络连接 |
| 证书校验失败 | 系统时间不对，校准时间 |
| 智谱「不存在 coding plan」 | Key 有效但账号是按量付费（无 Coding Plan），按量余额官方无公开 API，请手动录入 |
| OpenAI 查询失败 | OpenAI 已关闭公开余额接口，请手动维护余额 |

## 在线更新（V3.4 起）

升级**不用重新下载整个包**——拿到几 KB 的「更新包_Vx.x.zip」就行：

**本地更新（默认，不联网）**：

1. 把「更新包_Vx.x.zip」放进 `本地代理/` 目录（不用解压）；
2. 网页「帮助文档 → 版本与更新」点「检查更新」，或直接访问 `http://127.0.0.1:8787/api/update/check`；
3. 看到新版本和更新内容后点「一键更新」——旧文件自动备份到 `备份/V<旧版本>/`；
4. **生效方式**（按更新内容区分）：
   - 只更新了**代理文件**（.py 等）→ 重启代理生效；
   - 更新了**前端页面**（.tsx/.ts/.css 等）→ dev 模式热更新，刷新浏览器即可；
   - 改了依赖/配置 → 挂机守护会自动重启网页服务（或手动重启）。

> 配置留空时代理会自动扫描本目录最新的 `.zip` 更新包；也可以在 `update_manifest_url` 里直接填更新包路径。

**远程更新（可选，适合发布后分发）**：`update_manifest_url` 填远程 `version.json` 的 https 地址（GitHub raw 或对象存储），流程同上。

| 接口 | 作用 |
|---|---|
| `GET /api/version` | 查看当前版本号 |
| `GET /api/update/check` | 检查是否有新版本（显示更新内容） |
| `POST /api/update/apply` | 一键更新（旧文件自动备份） |

- **更新范围**：`proxy_files`（代理目录文件）+ `app_files`（前端源码，如 src/pages/*.tsx）两类都能更新；
- 安全限制：白名单扩展名（代理 .py/.md/.json/.txt + 前端 .ts/.tsx/.css/.js/.html）、禁止路径穿越、远程文件仅允许 https 源；
- 历史更新内容见包根目录《版本更新日志.md》。

## Key 隐私策略

- **界面不显示 Key**：账号列表、详情、编辑弹窗均无 Key 内容；
- **配置文件不落明文**：保存时自动转为 `enc1:` 混淆存储，代理查询时自动解密；旧配置的明文 Key 在代理启动时自动迁移；
- **Key 由你保管**：请到各平台官网 API Keys 页面查看/重置 Key，本工具不提供找回；
- 代理只绑定 `127.0.0.1`，请勿改成 `0.0.0.0`，否则局域网内任何人都能调用本机代理接口。

## 安全提示

- `accounts_config.json` 仍包含可解密的 Key 信息，请勿发给任何人；
- 查询失败（Key 错误、网络不通）时自动回退配置里的手动余额，页面不会崩，错误原因会在页面上明确提示。
